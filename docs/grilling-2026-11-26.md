# Design grilling outcome — 2026-11-26

Settled decisions from the initial design interview. Input for `/to-spec`. Terms follow `GLOSSARY.md`; hard-to-reverse choices are in `docs/adr/`.

## Shape
- Single-user, self-hosted (ADR 0001). One Rust binary + Docker image; TOML/env config; one data dir (SQLite + EPUB cache).
- One crate. A core module owns domain + DB (Feeds, Articles, Folders, Digests, Read/Starred). Web UI, OPDS, and MCP are thin adapters over the core and never touch SQL. Fetch/parse, discovery, extraction, and EPUB building are separate modules with narrow interfaces.
- Tests run against real SQLite and recorded HTTP fixtures.
- Stack: axum, sqlx (SQLite + FTS5), reqwest, feed-rs, rmcp (Streamable HTTP), askama + htmx, dom_smoothie (readability), epub-builder, image, tokio tasks. AT Protocol via hand-written XRPC calls (resolve handle/DID → DID doc → PDS → `com.atproto.repo.listRecords`).

## Feeds
- Kinds: RSS, Atom, JSON Feed, standard.site Publication (ADR 0002 — polled from the PDS, no firehose).
- Add by any URL: is it a feed → HTML `<link rel="alternate">` → `/.well-known/site.standard.publication`; also at-uri or handle. If both RSS and standard.site exist, show all options, default to RSS, no merging. MCP `add_feed` uses the same default.
- Each Feed in at most one Folder. OPML import/export maps Folders ↔ categories.
- Polling per Feed, default 30 min, conditional GET (ETag/Last-Modified), exponential backoff on error; persistently failing Feeds are flagged, never auto-deleted. No WebSub in v1.

## Articles
- Identity within a Feed: guid/id → link → hash(title+date); standard.site uses the document AT-URI. Upstream changes update in place and keep Read/Starred. No cross-Feed dedup.
- Feed Content is always stored. Extracted Content is a per-Feed toggle (off by default; on by default for Publications), attempted once on arrival; on failure, fall back to Feed Content, record the reason, offer manual re-extract in the UI.
- standard.site: Feed Content = `textContent` (fallback `description`); canonical URL = publication `url` + document `path`. Per-format renderers (e.g. Leaflet) deferred.
- Read = opened in the web UI or explicitly marked (by the person, an agent, or an OPDS mark-read link). Agent fetches, EPUB downloads, and Digest inclusion never mark Read.
- Retention: Read non-Starred deleted after 90 days (configurable); Starred kept forever; unread capped per Feed (default 1000, oldest dropped).
- No tags in v1.

## Auth
- One password. Web UI: session cookie. OPDS: HTTP Basic with the same password. MCP: per-agent bearer tokens, revocable in the UI.
- Plain HTTP; TLS is the operator's reverse proxy / Tailscale.

## Web UI (v1)
- Feed list with Folders + unread counts, article list and view, search, add Feed with discovery, OPML import/export, per-Feed settings (extraction, images, interval, Folder), failing-Feed flags, MCP token management, keyboard shortcuts (j/k/s/m).
- Out: themes, drag-and-drop, PWA/offline.

## OPDS (target: CrossPoint on Xteink X4, also KOReader)
- OPDS 1.2 (Atom). EPUB only (`application/epub+zip`), HTTP Basic, OpenSearch, pagination.
- Root: Unread (newest first, paged) · Starred · Folders → Feeds → unread Articles · Digests · Search. Read Articles hidden except under Starred. Feed icon as cover.
- Mark-read via GET navigation links under `/opds` only (ADR 0003): a "Mark read" list of recent downloads, and "mark all Read" per Digest.
- EPUB images: downscaled to ≤480px wide, grayscale JPEG, tracking pixels and tiny images dropped, per-Article byte cap; per-Feed "no images" option.
- Per-Article EPUBs plus Digests.
- Digests are snapshots (ADR 0004). Scope: all unread / Folder / Feed / Starred; newest 50 by default; a section per Feed, chapters oldest→newest; date in filename. Creating one marks nothing Read. Not scheduled in v1.
- No KOReader progress sync (rejected).

## MCP
- Tools only (no resources): `list_feeds`, `list_articles` (filter by Feed/Folder/unread/starred/since; paginated), `search_articles` (FTS), `get_article`, `set_read`, `set_starred` (batch), `add_feed`. No deletes, no Folder or Feed-settings changes.
- `list_articles`/`search_articles` return metadata + excerpt, never bodies.
- `get_article` returns metadata, link, and excerpt by default; the body (Extracted Content if present, otherwise Feed Content, as markdown) only with `include_content: true`, sent in ~20k-character pieces via `next_offset`.
- Newer MCP spec revisions ("MCP v2") are out of scope for now.
